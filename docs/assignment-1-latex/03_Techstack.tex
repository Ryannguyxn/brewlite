\section{\texorpdfstring{\textbf{5. Kiến trúc hệ thống}}{5. Kiến trúc hệ thống}}\label{05-techstack:kiux1ebfn-truxfac-hux1ec7-thux1ed1ng}

Client (Next.js) → REST/JSON → NestJS (Auth / Product / Cart-Order / Payment / Loyalty modules) → PostgreSQL qua Prisma. NestJS gọi Mock Payment Service nội bộ. Một backend duy nhất (modular monolith), không có API gateway, event bus hay dịch vụ độc lập.

Luồng nghiệp vụ: Menu → Chi tiết (size/topping) → Cart → JWT login (nếu cần) → POST /orders → mock POST /payments → xác nhận → /orders/me. API trả trạng thái rõ ràng để UI xử lý loading/empty/error.

\section{\texorpdfstring{\textbf{7. Chuẩn xử lý nghiệp vụ Task 10}}{7. Chuẩn xử lý nghiệp vụ Task 10}}\label{05-techstack:chuux1ea9n-xux1eed-luxfd-nghiux1ec7p-vux1ee5-task-10}

\begin{quote}
- State machine: PENDING → PAID → PREPARING → READY → COMPLETED; cho phép PAYMENT\_FAILED, CANCELLED theo sơ đồ của đề; mọi transition khác phải bị chặn.

- Idempotency: lưu khóa yêu cầu và enforce uniqueness trong DB; cùng key + cùng payload không tạo giao dịch/đơn kép; khác payload phải bị từ chối an toàn.

- Concurrency: transaction + optimistic locking hoặc atomic stock decrement bảo đảm không bán vượt tồn kho; phải có test đặt song song.

- Promotion/Loyalty: kiểm tra mã giảm giá hợp lệ, cộng điểm chỉ sau khi đơn PAID; không cộng trùng khi retry.
\end{quote}

\section{\texorpdfstring{\textbf{9. Workflow \& engineering standards}}{9. Workflow \& engineering standards}}\label{05-techstack:workflow-engineering-standards}

\begin{quote}
- Nhánh ổn định: main; nhánh tích hợp: dev; tạo nhánh ngắn hạn từ dev theo issue Jira (ví dụ feat/SCRUM-9-project-docs).

- Commit gắn issue key, ví dụ: SCRUM-9 docs: thêm Project Charter và Techstack. Automation Jira phụ thuộc cấu hình tích hợp hiện có.

- Tạo PR từ feature → dev; ít nhất một thành viên khác review, check build/test trước khi merge; không push trực tiếp main/dev nếu protected.

- Cuối Sprint sau review/QA: PR dev → main để tạo bản bàn giao ổn định.

- Format TypeScript nhất quán, ESLint/Prettier theo repository; DTO/API contract và migration phải review.

- Các pull request thay đổi business logic cần cập nhật test và tài liệu liên quan.
\end{quote}

\section{\texorpdfstring{\textbf{10. Kiểm thử và Definition of Done}}{10. Kiểm thử và Definition of Done}}\label{05-techstack:kiux1ec3m-thux1eed-vuxe0-definition-of-done}

\begin{quote}
- Unit tests: giá size/topping, tính total, state transitions, valid coupon/loyalty.

- Integration tests: auth JWT, create order, payment success/failure, order history; validate input.

- Concurrency/idempotency tests: cùng key 2 lần chỉ một kết quả thanh toán; nhiều yêu cầu cùng lúc không vượt stock.

- DoD: code build được; acceptance criteria đạt; Git commit + PR review; API validate, UI loading/error; README có hướng dẫn chạy.
\end{quote}
